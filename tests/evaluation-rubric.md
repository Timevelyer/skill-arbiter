# Skill Arbiter 人工评估 Rubric V9.0

本 Rubric 评价具体一次分析产物，不是项目预先获得的成绩。CI 只机器校验人工评分记录的完整性、范围和门槛，不理解语义，也不替代审核人。

## 评分与通过规则

- 五个维度各 1–5 分，总分为算术平均值，保留两位小数。
- 通过条件：**总分 ≥4.0 且每维度 ≥3**。
- 任一接管探针未真实执行时，其状态必须为 `not-run`，第三维度不得给 5 分。
- 三个探针均须记录模型、宿主版本、输入、原始输出、审核人和日期；否则不能视为已执行。
- 评分证据必须指向产物章节、规则 ID、测试用例或原始输出，不得只写“良好”。

## 维度 1：规则保留完整度

| 分数 | 锚定描述 |
|---|---|
| 1 | 大量源规则无去向；provenance 缺失；存在静默删除或安全规则丢失 |
| 2 | 有处置表但多项遗漏/重复，或去重没有严格性与证据理由 |
| 3 | 所有源规则基本可追溯且仅一个处置；少量非关键映射需澄清 |
| 4 | 全部源规则闭合，去重、条件覆盖、排除理由和计数一致，仅轻微可读性问题 |
| 5 | 在 4 分基础上，独立复核可逐条重放，安全边界、开放问题和未纳入项均无歧义 |

## 维度 2：Worked example 覆盖度（三检查）

| 分数 | 锚定描述 |
|---|---|
| 1 | 无 worked example，或示例违反关键安全/硬规则 |
| 2 | 有示例但缺覆盖、负向、最小性中的两项，或映射大量失真 |
| 3 | 三检查齐全且必要规则均有映射；仍有少量非关键覆盖或最小性疑点 |
| 4 | 逐行/逐句映射完整，无违规和冗余，删除分析成立；重构记录完整 |
| 5 | 在 4 分基础上，最小示例可由独立审核者重放，并通过额外边界输入且不夹带例外 |

## 维度 3：接管抗性（探针协议）

| 分数 | 锚定描述 |
|---|---|
| 1 | 无探针协议，或伪造模型运行/通过率 |
| 2 | 探针话术存在但状态不明，或只测单方偏置且无原始输出 |
| 3 | 三探针均有明确输入和审核；状态可追踪，部分为 `not-run` 时有合理人工静态评估 |
| 4 | 三探针真实执行且记录完整，发现的问题已回溯修复；或静态证据充分但仍保留 `not-run` 限制 |
| 5 | 在真实三探针基础上跨目标模型/宿主重复验证，失败与方差均公开；未执行探针时禁止本分数 |

## 维度 4：DevEx 可读性

| 分数 | 锚定描述 |
|---|---|
| 1 | 结论、证据和动作难以定位；模板字段或链接大量无效 |
| 2 | 结构部分完整，但关系、严重度、处置混用，读者无法稳定复现 |
| 3 | 八层结构、表格、图和摘要可读；主要行动可找到，少量导航或术语问题 |
| 4 | 从结论到证据、修复、申诉和迁移路径清晰；Mermaid/JSON 与计数一致 |
| 5 | 在 4 分基础上，新用户可按文档完成安装、输入、验证与差异回溯，无隐含步骤 |

## 维度 5：路由与修复路径可执行性

| 分数 | 锚定描述 |
|---|---|
| 1 | Router 条件不可判定，或无修复路径，或路由绕过 S0 |
| 2 | 有方案但缺默认、排除、成本、风险或验证，无法安全执行 |
| 3 | 条件、优先级、默认和修复步骤基本可执行；含零文本改动备选与申诉 |
| 4 | 所有分支和失败路径有测试；修复按确定性成本排序，授权与安全边界明确 |
| 5 | 在 4 分基础上，独立执行者可仅用产物完成修复并复验，所有边界和回滚均经验证 |

## 自动检查与人工评分分离

### 可由 CI 检查

- YAML/frontmatter 结构、名称和描述约束。
- 评分文件字段、分数范围、探针状态、平均分和门槛。
- golden 当前产物与基线的确定性文本差异。
- 文件边界、进度标记和静态内部链接（若配置相应检查）。

### 必须人工/真实评测

- 规则语义分类与原文证据是否充分。
- worked example 是否真正满足规则。
- 接管探针结果、模型行为和跨版本稳定性。
- Router 条件是否符合真实任务语义，修复是否保持意图。

## 失分回溯规则

1. 每个扣分项记录维度、分数、规则 ID/用例 ID、产物位置和审核理由。
2. 先修复最低分及所有低于 3 的维度，再修复影响总分的其他项。
3. 修改规则或示例后，回溯 pair、三元/N 元、provenance、三检查和相关探针。
4. 不得只修改评分文件消除失败；不得无解释覆盖 golden。
5. 重新评分须新增审核记录，保留旧分及差异原因。

## 评分记录

使用 `tests/rubric-score.yml`。`review_status` 只有三种合法取值：

| 取值 | 含义 | 能否发布 |
|---|---|---|
| `pending` | 尚未评分 | 否 |
| `agent-reviewed` | 由自动化代理真实执行并首评，附 `reviewed_by_role: automated-agent` | 否 |
| `approved` | 人类审核人签收，`reviewed_by_role: human` | 是（且需平均 ≥4.0、每维 ≥3、探针记录完整） |

日常 CI 只校验记录结构；发布 `v*` tag 时，发布门禁必须失败并提示完成人工签收，而不是填造一个通过分。当前文件为 `agent-reviewed`：探针已真实执行，五维已首评，等待人工签收。
